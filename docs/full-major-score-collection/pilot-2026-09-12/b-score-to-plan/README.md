## 文件与复核

- `plan-package/`：初始计划增量、来源元数据、全部 20 校 plans 审计。
- `score-package/`：2 条实际专业分增量、来源元数据、全部 20 校 major-scores 审计。
- `scope-review-observations.json`：计划与专业分范围的分别核查结论，以及仅供追查的名称差异。
- `verification.json`、`plan-qa.json`：逐源数量、SHA256、当前 API 与既有分数对照、独立视觉 QA。
- `preflight.json`、`score-preflight.json`：不带 --apply 的只读增量导入预检。

`PUBLIC-FILES.json` 是公有仓库复制的严格白名单。不要整目录复制。`raw/`、原始 targets.json、API 全响应、图片/PDF/渲染图/全文、全国表格中间件、调试输出均仅本地保留。请求脚本不保存 Cookie/CSRF 值；清洗后的统计事实和元数据可公开。source 中的 archiveFile 指向本地证据档案，不是公开下载承诺。

## 重放与验收

在本目录使用 Python 3 运行 collect.py 和相应 requests-N.json 可重取已观察的官方公开请求；ECNU/UIBE/OUC 需 session_query.py 配合相应 sessions*.json，按官方匿名网页会话交换，不绕过登录或验证码。原始请求和参数保留在本地；公有来源元数据包含实际采纳的 URL/查询参数与哈希。

离线重建需本地 raw 证据和 pdfplumber：先运行 `python3 extract_pdf.py`，再运行 `python3 build_reviews.py --repo <repo>`，最后运行 `python3 verify.py --repo <repo>`。两个 importer 以包目录为参数、不加 --apply 可只读预检。verify.py 的既有记录检查以本轮导入前基线为准；整合后新增分数 ID 已存在时，应使用仓库整合后的验证，而不是再期待这些 ID 不存在。

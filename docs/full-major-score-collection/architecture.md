# 全量专业录取分采集：技术执行建议

2026-09-12；只读盘点仓库 `1e8e991acb3a41f37ca1693703195de494bc7360`。本文件没有联网验证，没有新增分数，没有设置定时任务，也没有修改网站。所列成功、旧年和受限情况均是仓库已归档批次的记录。

## 交付目标和“完整”的边界

把网站全部院校条目建立为任务台账，逐个完成官方入口发现、2026 广西范围查询、证据判定、数据或缺口展示，不再以 20 校为项目上限。原有分数、补录资料和来源应被复用，不能从头重查全部学校。

“全部学校完成一轮有边界核查”“某官方来源的本年广西表全部采完”“该校所有实际录取专业都已公开”是三个不同结论。前两个能通过工作和证据验收；第三个只有存在完整官方目录、类别及轮次说明时才能宣称。专业分母缺失时，显示已核实条数和缺口，不计算虚假的全专业覆盖率。

现有快照有 1,255 条专业分、37 个学校代码、1,101 项来源；207 条学校审查说明中 129 条显式标记 `auditKind=major-scores`；兼容早期 `review-major-gap-*` 和 `review-major-collected-*` ID 后，实际共有 154 条专业分审查说明，覆盖 146 个院校代码。审查状态有 24 种旧写法，应加规范化的工作台账，保留原说明和历史检查范围。

## 先统一流程，再按来源类型并行

复用现有导入器和字段模型。`scripts/import-major-score-batch.mjs` 已处理来源存在性、2026/广西/科类/分数口径、专业与组参考分分离、数值矛盾、重复身份、证据支持更正及失败回滚。主要缺失在发现任务、组合覆盖和可恢复调度，不在换一套录取数据格式。

复用有两处边界：`site/coverage.js` 当前只用首轮投档线、计划和专业实际分构建学校集合，且全部 `coverageStatus` 固定为 `partial`，需要对照其他可展示数据路径后再确定全站任务分母；`scripts/report-score-review.mjs` 当前假设纯追加并保护旧记录/旧来源完全不变，实施有证据更正时应增加明确更正清单及专门报告分支，继续验证清单外旧数据完全不变，不能直接放松保护。

建议统一为以下阶段，适配器只负责各站差异：

1. `discover`：从已有考试院学校代码、官方招生主页和已归档入口出发，保存首页到分数页面的链接链；区分同校多校区、独立招生代码及网站委托平台。站名、域名片段和第三方搜索命中不能单独建立学校身份。
2. `inspect`：保存当前菜单和字段表头，提取年、省、科类、校区、类别、批次、轮次、专业等真实选项及分页规则。字段映射按校配置，不能只看变量名。
3. `enumerate`：生成本年广西的实际菜单组合，标识每个组合是否已请求、结果数量、排除数量和理由；旧年值只作为诊断对照，不能冒充本年可选类别。
4. `fetch`：共享主机限速、匿名会话、短超时、重试和证据落盘；同一主机的会话请求串行。HTTP 200 先检查 MIME、业务码和是否验证码 HTML，再进入数据解析。
5. `extract`：规范 JSON/HTML/Excel 数据；PDF 按页面、表格和坐标，图片按图号和行号保存统计事实。自动提取只产候选，不直接写站点。
6. `validate/review`：校验标题年省科类、实际录取口径、完整页数/行数、字段来源、数值、类别资格和冲突；独立复核之后生成三份既有导入文件。
7. `publish`：单个集成者执行预检、变更检查、回归、发布和线上核验。各采集者只写独立包，避免多人改共享 JSON。

适配器统一输出 `manifest + observations + evidence-rows + exclusions + school-scope`，随后转换为既有 `major-cutoffs-upsert.json`、`sources.json`、`school-audit-notes.json`。来源族和可复用脚本见 `source-families.json`；识别来源族不等于已经适配该校。

## 任务状态和验收台账

工作单元不能只有学校名。建议学校任务下挂入口任务，入口任务下挂 `2026 / 广西 / 学校代码 / 校区 / 科类 / 类别 / 批次 / 轮次` 查询组合；未知字段显式为未知，不拼接成已确认的组合。

将进度、观察结果和完整性分列，避免一个状态同时表达三件事：

| 维度 | 建议值 | 要求 |
| --- | --- | --- |
| 处理进度 | queued / discovered / fetching / parsed / reviewing / ready / published / needs-attention | 只表示执行阶段 |
| 来源观察 | current-major-rows / current-aggregate-only / current-filing-only / old-year-only / current-menu-missing / successful-empty / explicit-no-match / business-error / transport-error / access-challenge / personal-login-only / no-located-source | 同一学校可有多个观察值 |
| 范围完整性 | unknown / partial / source-scope-complete / school-scope-complete | 最后一级需本年全部官方类别与轮次清单支持；一般不能轻易使用 |
| 内容审核 | unreviewed / verified / source-conflict / rejected | 冲突记录可公开说明，不能参与比较 |

每次观察至少保存 `schoolCode, sourceId, requestedScope, menuYear, menuFingerprint, observedAt, requestFingerprint, httpStatus, businessStatus, resultCount, sourceScope, archiveFingerprint, reviewer, nextAction`。保留失败尝试，但只有语义成功、参数正确的空表才进入 `successful-empty`；支持旧年同条件正向对照时记录对照。未回显参数的响应必须联结对应请求证据，不能把空响应单独当成完整查询证明。

网页显示读者能理解的原因：已收录、已收录部分、官方来源当前仅见旧年、只有学校/组汇总、已查组合未返回记录、访问受限、尚未完成核查。专业记录另外显示最低分、年份、统计口径、批次/轮次、原始来源和未公开字段。组参考分保留清晰标签，不能填进专业实际分缺口；暂停的院校卡片合并不属于本次实施依赖。

## 证据、更正与去重

- 来源对象按每次抓取版本归档：原响应哈希与脱敏归档哈希分开，保留原 URL、重定向后 URL、请求方法/公开参数、访问时间、实际发布日、统计年份、解析器版本及来源身份链接。Cookie、CSRF、FineUI 状态及个人查询内容不入公开仓库。
- 官方文章/PDF/图片全文留本地；公开包只含白名单脚本、公开请求参数、统计事实转录、排除说明和 QA。不要把“公开可访问”自动当成“整篇可再发布”。离线重建与重新抓取分别标记，不能用重建时间刷新核查日期。
- `sourcePage / sourceTable / sourceRow` 等定位保留；位次、专业组、选科、实际人数只取直接证据。首医 `xkkm` 实际是年制，证明不能跨校共享猜测字段名；专业国标代码不能转成广西填报代码。
- 首先复用现有身份去重 `year + schoolCode + track + batch + group + major + round + admissionType`。另外加入候选重复检查，捕捉“未知批次后来明确”“原名后来规范”“官网新旧表同一行”造成的新 ID 重复；这类匹配需证据与人工判断，不能仅按分数或模糊专业名称合并。
- 已发布记录采用稳定 ID 和有字段证据的更正；新增来源版本另给 ID，旧批次包保持冻结，并在更正日志注明旧值、新值、依据、影响范围。专业名称或分数冲突保留原值、标记待核，来源改变触发重新复核。
- 查询完全返回不等于录取专业完整。例如海大本年 9 类组合已查并排除预科汇总，首医本年专业菜单 6 项与 6 行相符；陕师 PDF 只有 2 个明确专业，其余汇总仍是缺口。完整性应挂到具体来源和范围。

## 重试与效率：建议参数，尚未启用

下列仅为初始工程假设，根据首批实际延迟和成功率调整，不是完成日期承诺。

- 同一主机默认 1 个在途请求、间隔 1–2 秒；全局 4–6 个独立主机。遇到公开站限速先减速，尊重 `Retry-After`；不通过大量重复请求试探验证。
- 网络超时/偶发 5xx 当轮最多重试 2 次，退避约 5/20 秒；仍失败转 `transport-error`。403/412/验证码/个人账号入口停止自动内容请求，尝试官网提供的另一公开发布渠道，不能把受限页转成空表。
- 已有有效空表、旧年菜单或仅汇总来源：优先轻量检查首页/目录/菜单指纹，默认 7 天再看；连续两次无变化后 14–30 天再看。菜单或公告发生变化时立即生成重采任务。已发布专业表可约 7 天复查更正，连续稳定后延长；学校明确发布新版本时优先。
- 初次全量发现不依赖此重试周期；未查学校与已找到本年专业表应优先推进，避免每天对相同旧年空接口耗费整批工作。
- 每校自动发现与适配设置软预算；超出后记录已尝试入口及下一步转人工队列，不让一个验证码或高度定制系统阻塞全量扫描。预算用于分流，不把尚未核实的学校标成完成。

## 执行波次与退出条件

| 波次 | 主要工作 | 可检查成果 |
| --- | --- | --- |
| 0. 基线和台账 | 固定全站学校代码集合；导入既有分数、入口、逐校说明；保留本科/专科、独立校区及特殊类别范围 | 每个学校都有任务；已核实、待查、字段缺失和范围不明可分别统计；既有数据无回退 |
| 1. 高复用来源 | 优先已发现本年数据的入口，随后按来源族批量扫描菜单；保留原分数优先级作为同等条件下排序 | 主干适配器各有真实正例、空例和失败例；记录每校/组合行数与覆盖证明 |
| 2. 静态材料 | 并行遍查官网分数栏目、录取快讯、附件与官方转载；结构化表先行、图片/PDF 单列人审 | 本年广西专业统计事实尽量入库；仅汇总、旧年及混合口径全部有排除说明 |
| 3. 困难和缺失字段 | 定制系统、入口迁移、受限来源、名称矛盾、校区身份、排名/批次/轮次缺口 | 明确可修复项与外部缺口，不用组线或旧年数据补猜；待核原因可见 |
| 4. 全量闭环 | 对全部学校任务进行状态审查；对每个正源的菜单/分页/附件做完整性检查；全站渲染与检索验证 | 全部目标有可定位的检查记录或明确待办；可获得的已核实数据已发布；剩余缺口及重查条件清晰 |

建议波次 1 用 60–100 校混合来源作为吞吐样本，统计入口发现率、适配成功率、有效专业行占比及人工审核耗时，之后再估算剩余工作；不是把项目重新限定为 100 校。工程估算公式采用 `剩余学校数 × 各来源族实测平均处理/审核量 + 异常队列预算`，外部尚未发布的数据另列，不计作可承诺采完的工时。

批量处理与批量发布分开：每包可以覆盖多个学校；已独立复核的一包即可发布，不能等全部学校完成后才让考生使用。每次发布报告给出新覆盖学校、新增专业分、原有学校补全、更正、剩余缺口和当次范围，避免单独用“增加了多少来源”表示效果。

## 每次发布的验收

1. 数据：所有新增行都能回到直接官方表；符合本年广西专业实际最低分范围；类别、未知项与冲突保留；源表数量/分页/菜单组合校验；OCR/PDF关键数字和专业名独立逐行复核。
2. 工程：先运行导入器只读预检，再执行增量导入；运行现有相关测试、数据校验与覆盖统计；共享逻辑或 UI 变更才增加对应行为测试。确认旧数据保护或每项更正的证据，不用大量镜像实现的测试替代事实审核。
3. 展示：实际浏览器抽查每种新增数据形态、无数据学校、待核冲突、专项、未知组码及来源跳转；新增专业可通过学校、专业、科类和分数筛选，筛选计数与数据一致。
4. 部署：确认精确提交的 GitHub Actions 成功；站点运行文件 HTTP 状态及哈希与目标提交一致；浏览器确认最新记录可见。修改 `app.js` 时同步入口版本，避免上一批已出现的缓存旧脚本问题。

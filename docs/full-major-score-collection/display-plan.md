# 全量专业录取分搜集：网站展示与验收方案

核查日期：2026-09-12。只读基线：`1e8e991acb3a41f37ca1693703195de494bc7360`。本文件依据本地网站代码、当前数据和现有测试；先完成只读盘点，再实施第五节列明的首阶段展示修复，没有新增分数数据。用户已暂缓的“将专业组统一合并为院校条目”不在本方案中。

## 1. 当前状态与真实问题

| 本地实测项目 | 当前值 | 含义 |
|---|---:|---|
| 网站院校范围 | 1,961 个院校代码 | `cutoffs ∪ plans ∪ major-cutoffs` 与覆盖台账一致；不能未经实体核验直接当作独立大学数 |

当前 `buildCoverage()` 将全部 1,961 校标为 `partial`，这是正确的保守边界，但只统计计划字段缺口和专业分条数；它没有专业分“应有多少条”的分母，也没有逐专业闭合状态。简单将 37 / 1,961 改写成“专业录取分覆盖率”会误导。

### 实施前发现并复现的展示问题

1. **专业分页面点击“重置”会隐藏大部分已收录内容。** `changeView()` 首次进入将轮次设为 `all`，但 `filters.reset()` 又恢复 HTML 的“首轮”。使用当前数据的 JSDOM 实际交互复现：同为默认物理类、本科普通批、一般计划，进入专业分页为 462 条 / 21 校，点重置变成 76 条 / 2 校。应按视图设置重置默认值，并测试。
2. **缺口页“已收录”筛选不是“已完成”。** 目前 `r.majorCutoffs > 0` 即脱离“尚未收录专业线”列表；已采一条的学校仍有大量未核查专业、科类或类别时，页面没有相应筛选项。
3. **缺口页“本轮复查”目前汇总历史批次及计划核查。** 应区分“专业录取分已核查学校”与“计划核查”，显示最新核查结论和日期，历史记录折叠保留；不要将最后补采日期解释为全库重查日期。
4. **专业计划与真实专业分尚无逐专业双向关联。** 当前计划详情只能跳到该校同科类全部专业分；实际专业分详情没有回到本专业计划的入口。当前计划卡片的分数始终是组线，不能在全量补采时静默替换成一个猜配的专业分。
5. **空搜索结果不能区分被筛掉和未采到。** 专业组空结果有“到专业计划中搜索”，专业分空结果没有直接查看该校专业分缺口/官方入口的路径。默认普通批、一般计划也会隐藏批次未知或受限制类别，应提供清楚的当前条件和一键查看该校全部已收录记录。
6. **来源状态代码有未映射项。** 现有专业分审计中 `partial`、`old-year-material-only` 回退到“详见核查记录”；扩大量前应统一状态语义，旧记录兼容，不从状态名字推断是否完整。

代码依据：`site/app.js` 的 `initialize / schoolMajorScores / render / openDetail / renderGaps / renderSources / changeView / reset`；`site/coverage.js` 的 `buildCoverage`；`site/logic.js` 的 `exactGroupKey / filterRows / comparableScore`；`tests/app.test.mjs`、`tests/logic.test.mjs`。

## 2. 怎样定义“完整”，使进度可验收

建议同时保留三种口径，不能合并成一个百分比：

### A. 院校核查进度：有明确固定分母

- 第一阶段冻结 1,961 个院校代码清单及版本。此后新增学校另报“范围新增”，不悄悄变更分母。
- 展示“已完成本阶段官方来源核查 X / 1,961”。完成核查必须有：具体官网入口、2026 广西查询/文章的统计范围、实际查过的科类和类别、时间、结果、证据定位、下一步。
- 访问受限和未找到本年专业分仍是有效核查结果；它们不能计作“数据已完整”。只浏览学校首页也不能计作完整核查。
- 当前有 146 校既有专业分核查记录，但能否满足统一的本阶段核查清单应逐条评估，不直接全算完成。

### B. 官方已公布范围采集进度：有证据限定的分母

- 对一份公开统计表或一个可完整枚举的查询系统，记录本年广西的科类 × 批次 × 招生类别 × 校区等实际筛选范围及所有分页。
- 比较“原表可入库专业记录 N，已入库 N，冲突保留 C，排除 E（逐类说明）”，用行号/原始记录身份清单核对遗漏和重复。
- 只有全部可枚举范围核对完成，才显示“本来源公布范围已采全”；它不等于学校公布了所有专业或学校实际录取分全覆盖。
- 若学校仅公布部分科类或专项，应按该范围标注，例如“物理类普通本科公布表已采全，历史类范围待核”，不能给整个学校绿色完成标记。

### C. 专业闭合进度：需要计划分母证据

- 在取得一份完整的 2026 广西专业计划/学校全专业录取清单后，才能建立“应核查专业条目”分母。
- 每个条目以官方可证实的年份、院校身份、科类、批次、招生类别、专业组、正式专业/招生大类、校区或定向地区等区分。同名专业不同培养方式不能去重成一个专业；轮次作为独立记录维度。
- 每个预期条目必须落在：已取得适用录取分、官方明确无录取/取消、官方仅有汇总、未公布或未取得、关联证据不足、原文冲突。零录取和取消需要官方证据，不能由分数空值推断。
- 没有可靠分母时显示“已收录 N 条；专业总量待核”，比例为不可计算，不能显示 0% 或 100%。有计划分母也要显示范围，不假定征集变更、追加或取消已全掌握。
- “专业分采集覆盖”和“与广西计划精确关联覆盖”分开统计；缺组码不妨碍展示原始专业分，但必须保留关联待核。

状态建议用两个独立字段：`reviewStatus`（待查、已查、访问受限等）与 `coverageStatus`（无可用专业分、部分收录、本来源范围已采全、已验证专业范围闭合）。冲突、组码待核、批次待核等做独立问题标记。这样“查过但没数据”和“有数据但没采全”都可准确筛选。

## 3. 最小必要的 UI 分期

### 第一期：让全量工作可见，并修复检索遗漏

- 保留现有专业组、计划、专业分三种入口和分页，不做院校卡片合并。
- 顶部与缺口页显示：目标院校代码总数、专业分已核查数、至少有一条专业分的院校数、专业分记录数、冲突数。每项明确口径。
- 缺口页增加“待专业分核查”“部分专业分”“本来源范围已采全”“访问受限”“有关联/原文待核项”等筛选；学校卡片显示最新专业分核查、仍缺的科类/类别/范围、来源入口和日期。
- 修复专业分页重置到首轮的问题。专业分页首次进入与重置默认保留全部录取轮次；当前招生资格与批次过滤条件必须可见。
- 针对指定学校无结果，显示是“该科类暂无记录”“本条件排除了已收录记录”或“该校尚无专业分”，并给出“查看全部已收录专业分”“查看核查结果及官方来源”。未查过不写成未公布。
- 仅在用户主动切到“全部”时展示所有资格类别；不得把资格未知归为一般计划。

验收：覆盖台账、公开报告与页面总数自动一致；每个院校代码都能搜索到缺口状态；146 校专业分审计（含早期兼容记录）均有清晰文字；重置前后没有因隐式首轮过滤丢失汇总分；4 条现有冲突在卡片、筛选、详情、导出中维持隔离。

### 第二期：逐专业展示与证据匹配

- 专业详情显示本条分数、招生类别、批次、轮次、广西组码已核/待核、官方原文行、统计口径及核查日期；已知的培养、资格、学费和定向条件必须可见。
- 引入独立的“计划—专业分关联”记录，保留匹配身份、证据、状态及双方记录 ID。只有有证据的精确关联才展示为同一报考条目；相似名称仅可进入人工待核队列。
- 计划卡片继续明确显示组投档线；有精确关联时附加“该专业实际录取分”入口。不同轮次、类别的多个专业分全部列出，不选择最低一条掩盖范围。
- 专业分详情可跳回已核验的对应计划；没有精确关系显示“对应广西计划/组码待核”，仍可查看该校资料。
- 缺口页的专业范围明细列出应有条目及各自状态；只有完整计划范围已核验的学校显示分母。

验收：同名跨科类/跨组/跨类别/定向地区/首轮与征集不能串联；招生大类不能拆成下属专业分数；国家专业代码不冒充广西填报代号；未知字段不阻止原始专业分被查到；汇总不能作为首轮的精确录取结果。

### 第三期：为大量数据改善加载，持续发布

- 先保留当前 25 条结果分页与 20 校缺口分页。不需要为全量采集立即更换框架或后端。
- 初始化目前一次等待 11 个 JSON，共 8,746,697 字节未压缩；本地 gzip 合计 644,156 字节仅作文件量估计，不代表线上传输实测。当前即预渲染全部 1,101 条来源，尽管来源页隐藏。
- 首先按视图延迟渲染来源列表、特殊项目与缺口详情；来源目录分页/搜索。建立按院校代码、科类和审计范围的索引，避免每次输入对 1,961 校反复扫描全部审计记录。
- 数据增长后使用小型查询索引与按校/批次分片的详情/来源。全国专业搜索必须覆盖完整索引，不能只搜索已经打开的学校分片。
- 统一发布清单、版本和哈希，防止新索引配旧分片或缓存中的旧脚本；某视图数据失败应明确提示重试，不能按空表显示“零条”或假成功。
- 防抖与预计算检索字段是否需要，依据浏览器实测决定；搜索/排序不是 DOM 中只查当前页。保持原有备选记录 ID 稳定，导出可定位具体口径及来源。

建议性能验收目标（尚未测得，不是现状承诺）：以真实数据加 10 倍规模的可验证测试集，在固定桌面浏览器及一款移动设备/受限网络条件下记录冷启动、首次可查询、输入至结果更新、打开详情及分页的 p95；目标暖态筛选/分页不超过 300 ms、已载入详情不超过 200 ms，首屏显示可恢复加载状态不超过 1 s，受限网络下首屏可查询目标不超过 5 s。设备与网络配置写入报告；超标先定位下载、解析、全量排序或 DOM 渲染环节。若实测需要调整目标，必须记录原因与实际值。

## 4. 每次发布及最终完成验收

1. **事实和覆盖检查**：新增记录均有 2026、广西、正确科类、正式专业、实际最低录取分证据；原表行清单全部解释；学校代码稳定；去重与冲突隔离有效；不把计划人数当录取人数、组线当专业分。
2. **关联检查**：逐条验证匹配键及辅助证据；未知组码/批次/类别不能被默认补齐；全部字段补充来源可追溯。
3. **可发现性检查**：清空关键词，分别选物理/历史、全部已收录批次、全部招生资格、全部录取轮次、保留未知后，遍历每页，页面记录 ID 集合须等于专业分 JSON 集合，无丢失或重复。每校缺口入口、详情链接与来源链接可到达。
4. **回归检查**：保留现有有意义的筛选、轮次、定向条件、冲突、行号和导出回归；增加视图重置、来源状态完整映射、覆盖分母未知、不正确一对多匹配和分页全覆盖测试。无需为纯文案重复建立测试。
5. **真实浏览器检查**：桌面和手机宽度覆盖一般本科、高职、专项/定向、批次未知、组码未知、汇总、征集、原文冲突及暂无专业分学校；至少各一种完整点击路径，不能只依赖 JSDOM。
6. **发布检查**：精确提交的部署成功；页面脚本和数据版本一致；所需运行文件 HTTP 成功、哈希与本地匹配；实际页面新总数、随机新增院校详情、既有备选和来源跳转核验通过。
7. **全量阶段结束标准**：固定范围所有学校都有合格核查结论；找到且可公开读取的官方适用资料均已按来源范围采集和对账；每个已知专业条目已闭合或列明有证据的缺口；访问受限、未取得及无法确定专业总量的清单完整公开。不能把“全部学校查过”写成“全部学校专业录取分均已取得”。

## 5. 首阶段实施与验证记录

- 对当前 6 个主数据 JSON 及 11 个运行时 JSON 做本地计数/文件量检查，未请求外部网络。
- 在真实 JSON 的本地 JSDOM 交互中复现了重置问题，随后已修复：专业分视图点击重置保持 `round=all`。
- 已统一分数审计识别谓词：`note.auditKind === "major-scores" || /^review-major-(?:gap|collected)-/.test(note.id || "")`，避免把计划审计计入。旧年资料、部分收录及早期中文状态均有对应标签。
- 顶部与缺口页现动态展示 1,961 个目标院校代码、37 个已有部分专业分、109 个已核查仍未取得专业分、1,815 个尚待专业分核查；提示已有 146 个院校代码核查记录，仍不代表专业完整覆盖。目标院校分母使用全部投档轮次、计划和实际专业分的院校身份并集，避免只看首轮漏校。
- 缺口页已提供已有部分专业分、已核查仍未取得专业分、尚待专业分核查三种筛选。既有院校卡片组织方式保持不变，复查记录明确为历次记录。
- `node --test tests/app.test.mjs` 三项交互测试通过：真实数据筛选和既有流程、仅在征集出现的院校纳入目标范围、加载失败提示。新增断言还覆盖视图重置、旧分数审计计入、仅有计划审计不能计入、三个分组计数及状态标签。
- 本次没有执行全套测试、真实浏览器视觉/性能验收或生产发布；由主任务完成统一发布检查后记录结果。未添加任何未经核实的新分数。

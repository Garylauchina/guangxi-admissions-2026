# 2026 广西专业录取分：全量采集与展示计划

制定日期：2026-09-12。范围为网站已经收录的学校和招生通道，取消每次 20 校的项目上限。按官方来源的可获取程度并行处理，复核通过一包就发布一包。这里记录执行计划和首阶段成果，**不表示全量专业分已经采集完成**。

## 2. 怎样才算完成

分开验收以下三件事，不设置一个含义混杂的“完整率”：

1. **学校核查覆盖**：每个范围内的院校代码，都有本年广西专业分入口、实际检查范围、检查日期、证据和下一步。网络失败、只搜到旧年和验证码不能冒充“本年未录取”。
2. **来源采集完整**：某个已确认的官方来源，本年广西的实际菜单组合、页码、附件、物理/历史及招生类别均已枚举；每一行被收录、排除或列为待核，行数可核对。这个结论只针对注明的来源范围。
3. **学校专业覆盖完整**：取得本年完整专业计划及官方录取发布范围，逐专业、科类、类别、批次与轮次对账，明确未公布、未录取或汇总未拆分的情况，才可进一步判定。没有可靠分母时，只显示已收录条数和缺口，**不计算全专业覆盖率**。

本轮直接访问[广西阳光志愿计划查询入口](https://zyfz.gxeea.cn/Main/Jihua/JH_Chaxun_New.aspx)仍重定向至登录页；尚未取得完整省级专业计划。访问记录见 [province-plan-entry-check.json](province-plan-entry-check.json)，既有检索边界见 [全区计划获取核验](../province-plan-access.md)。公开来源采集继续推进，完整计划是逐专业对账的外部缺口。

“全量核查完成”的门槛是：1,961 个普通院校任务及 43 项特殊目录任务均经证据复审，不再有未处理任务；所有已找到且能够公开取得的合格专业数据都已入库并展示；受限、未找到本年表、仅汇总等剩余项逐一说明范围与原因。它不等于所有学校都公开了所有专业的录取分。发现新的有效招生代码时扩展清单、记录分母变化，不覆盖旧快照。

## 3. 推进顺序与交付物

| 阶段 | 处理工作 | 验收与交付 |
| --- | --- | --- |
| 0：全量建档 | 合并既有学校范围、专业分、计划、来源与核查结果；统一进度口径；修复影响专业分可见性的筛选问题 | 1,961 校都有稳定任务 ID；清单可重建；前端分开显示已有部分分、已查仍缺和尚待核查。本次先完成这一基础阶段 |
| 1：来源发现与采集试运行 | 覆盖 60–100 校的不同类型来源，包含已收录学校的补全和未核查学校；枚举实际菜单与分页；测量发现、提取和审核工作量 | 得到按来源类型拆分的成功率、人工复核量和剩余工作估算；首批可复用采集流程通过正例、空表与失败例验证。60–100 校是测量样本，非项目上限 |
| 2：全量滚动采集 | 将全部待查学校按可复用接口、网页表、附件、自定义系统分流；同类来源批量处理；已收录的 37 校同步补查其他科类、类别及轮次 | 每包有学校与查询范围、新增记录、补全、更正、排除和缺口清单；独立复核通过后滚动发布 |
| 3：疑难与字段补全 | PDF/图片逐行复核，处理入口迁移、校区和专业名称矛盾、有效空表、受限访问；核对 4 条现有冲突 | 可修复的冲突有直接证据；无法取得的字段保持未知；已有记录的专业组、科类、批次、轮次、人数与排名不靠猜测补齐 |
| 4：全量对账与展示验收 | 复审全部学校任务及特殊目录；校验每个正源完整性；有完整计划的学校做逐专业对账；检查网站全量性能和线上数据版本 | 全部范围有明确结论；可取得数据均已公开；学校缺口和专业缺口可查询；发布记录可追溯，用户能从分数结果回到官方原表 |

本轮先落实阶段 0，阶段 1 的实测结果再确定剩余时间。来源发现、定制适配和图片审核耗时差异很大，此时承诺固定天数或必得专业条数会失真。预计工作量按“各来源类型剩余任务 × 实测处理与复核耗时 + 异常处理”滚动更新；官方未公布的数据单列，不计作可保证采得的数据。

阶段 1 默认选 100 校：20 校已有部分专业分、20 校曾查无实际专业分、60 校从未独立核查。三个样本层均兼顾本科/高职、物理/历史、动态系统/静态材料，先复用现有已证实的入口，缺少类型时调整配额并记录原因。逐校记载发现、请求、提取、人工复核耗时及有效新增行数。学校发现每累计 100 个任务给出一次覆盖检查点；数据包只要完成独立复核即可提前发布，不能为凑数字跳过难校或审核。

采用三个采集/核查工作单元并行、一个集成复核单元的安排。各单元写独立研究包，集成者统一修改前端数据、执行检查和发布，避免共享 JSON 相互覆盖。

保留既有的高分优先顺序，在物理、历史各自队列内按首轮组线排序；组线只用于任务排序，不能充当专业录取分。来源复用度高的学校可以并行推进。本科与高职均有独立待办清单，不能因分数靠后永久不查；39 校特殊目录另行推进。

## 4. 采集流程与证据

复用现有增量导入器，不重写全部数据体系。现有可利用的来源类型包括 `ajax_lnfs`、`zsdata`、`zhinengdayi`、FineUI、自定义表单以及静态 HTML/PDF/图片；某校使用同一平台不意味着其参数和字段可以照搬。详细依据见 [采集架构](architecture.md)及[来源类型清单](source-families.json)。

每个学校依次执行：

1. 从官方学校主页/招生网验证入口及委托平台，记录链接链和校区身份。
2. 保存真实年、省、科类、招生类别、批次、轮次、页码菜单；按可选值枚举 2026 广西组合，不能盲试参数。
3. 获取并归档原响应，核对业务状态、表头、统计年份和适用范围；记录已查与未查组合。
4. 提取实际专业最低分及原表直接提供的最高分、均分、人数和位次，保留列名与行位置；计划人数与实际录取人数分开。
5. 独立复核、生成候选增量包，运行导入器预检；检查通过才写入站点。
6. 记录本次结论、剩余缺口、下一步和重查条件。

任务进度、来源观察、内容审核、完整性分列。旧年菜单、有效空表、业务错误、仅院校/组汇总、传输失败、个人登录和验证码分别记录。缺口不会因为“已运行过请求”而被清除。

每次观察保存学校代码、请求范围、真实菜单摘要、查询/响应摘要、结果行数、原始文件哈希、来源定位、检查日期和审核者。完整原文、匿名会话 Cookie、CSRF 和表单状态只留本地；公开仓库只放统计事实、必要来源元数据、白名单脚本与核查说明。离线重放不刷新原始检查日期。

统计年份必须由表头、查询条件及响应语义共同证明，**文章发表于 2026 年不等于数据属于 2026 年**。不引入其他年份补足本年，不用投档线代填专业分，不根据同分或相似专业名强配专业组。艺术体育、预科汇总、强基综合成绩等不混入普通专业分比较。

默认同一主机串行，独立主机有限并发；对限速和网络失败退避，对验证码/个人账号入口停止该通道的自动采集。优先寻找另一官方公开发布渠道。已经验证的旧年或空表，只有入口、菜单、公告变化或约定复查条件满足时再查，避免反复消耗在同一缺口上。此处是执行期间的调度规则，未建立定时自动化。

## 5. 网站怎样展示

详细分期和性能测量方法见 [展示方案](display-plan.md)。

- 专业分查询保留年份、科类、批次、轮次、招生类别、最低分及官方来源。来源冲突退出分数比较，但原文和原因可见；未知字段明确标注。
- “院校数据缺口”和“数据与方法”分别呈现总范围、有部分专业分、已查仍缺、尚待核查；来源采集完整性与学校专业完整性单独显示，有证据前保持未确认。
- 学校详情提供同校同科类已收录专业入口，并注明哪些来源、类别与轮次尚未取得。只有完整计划作分母时，才展示逐专业已匹配/待匹配/缺分的对账表。
- 专业分视图使用全部轮次作为默认与重置值；未知轮次的录取汇总不会被默认隐藏。依照用户此前决定，院校条目合并仍暂缓，不作为本次采集依赖。
- 数据增长后再按实测拆分：先制作轻量检索索引，来源全文和学校详情按需载入。保留全局专业搜索、稳定记录 ID、本地备选、CSV 导出和准确计数。不能以懒加载为由让未下载学校消失在搜索中。
- 每次发布都报告“新增覆盖学校、原校补全、新增实际专业分、更正、已审仍缺、尚待核查”，不只报告抓取页面数。

## 6. 每批验收和复现

数据验收：逐项核对年、省、学校身份、科类和实际专业口径；网页/接口核对全部页码与菜单组合，PDF/图片关键数字和专业名独立逐行复核；源表行数等于收录、排除和待核之和。特殊资格、加分口径、校区及未知项不丢失。

工程验收：增量预检、旧数据保护或有证据的更正记录、相关回归测试、全站数据校验、全量队列重新生成并校验一致。已有稳定身份不因规范名称或补充批次另造重复记录。

展示与发布验收：真实浏览器检查普通数据、特殊资格、汇总轮次、冲突记录、未核查学校及官方来源链接；精确提交的 GitHub Actions 成功后，核对线上运行文件与本地哈希并再查页面。测试通过不代表事实审核已经通过。

```sh
# 每次数据或核查记录更新后重建台账；日期指本次台账快照
node scripts/build-major-score-queue.mjs --as-of 2026-09-12
# 只读检查已发布台账与当前输入一致
node scripts/build-major-score-queue.mjs --check
npm test
npm run check
```

详细质量门槛见 [验收清单](acceptance.md)。本计划随阶段 1 实测更新工作量，但不会把“尚未核查”改名为“官方未发布”来提前结束项目。

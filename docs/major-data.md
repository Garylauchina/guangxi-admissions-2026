# 2026 广西专业录取线补充资料

核验日期：2026-09-10。仅从高校官方公开汇总表采集 2026 年数据；不含任何考生个人资料。

`major-cutoffs.json` 为专业实际录取结果，不能当成首轮专业组投档线。`plans-supplement.json` 是供主项目逐来源合并的计划补充表；与主项目已收集的同校同批次同科类计划可能重叠，不能直接相加。建议先选用已核实的录取前招生计划，再选择缺少覆盖的补充记录。

## 字段

每条专业结果含 `id`、`year`、`school`、`schoolCode`、`track`、`batch`、`group`、`major`、`score`、`scoreType`、`plannedCount`、`admittedCount`、`sourceId`、`note`、`round`、`admissionType`、`sourceRow`。

- `scoreType` 固定为“专业录取最低分”。齐齐哈尔原页以“录取分数线”命名，但数值表头为“投档成绩”；这一原始口径保留在注释，不能声称获得专业组线。
- `group` 未公布时为 `null`。东北石油、齐齐哈尔、山东交通没有直接取得同年同专业组关系，未据最低分或相似名称推定。
- `plannedCount` 必须来自明确的计划数列，`admittedCount` 必须来自明确的录取数列。缺失值均为 `null`。
- `round` 原文未区分时保存“录取汇总（轮次未分）”；齐齐哈尔保存“录取汇总（含征集）”；玉林征集保存“征集（次数未公布）”，不编造征集序号。
- `admissionType` 区分普通类、公费师范、精准专项、民族班、中外合作办学；资格限制仍须随记录展示。
- 玉林另含 `sourceTable` 与 `filingScoreInSource`。后者是高校表中另列的出档分，和 `score` 的专业最低分不是同一个字段。
- 玉林普通行的 `qualificationSourceId` 指向 `sources.json` 中同校同科类同组的考试院来源。
- 重庆工程的 `planSourceId` 指向独立录取前计划来源。关联仅归一化空白与中英文括号，科类和完整专业名须一致，15 行全部唯一对应。

计划表含标准计划字段及 `planBasis`。玉林、东北石油的计划数来自录取阶段公示，不是征集剩余数；但没有核实最初发布版本，所以明确标为“未核实最初发布版”。重庆工程计划发布于 2026-06-17，早于录取；这是“录取前计划”，不是“高考前计划”。它的 `subjectRule=any` 与空 `requiredSubjects` 表示原文“不限”；`all` 与 `["化学"]` 表示必须选择化学。其他未取得选科要求的记录为 `subjectRule=unknown`。

## 原文异常和限制

玉林公告的 3 行出档分与广西招生考试院同组首轮线不一致：历史 119 组一行显示 492，而考试院为 461；历史 912 组两行显示 464，而考试院为 457。原文专业最低分分别为 461、457、465，均保留；另存冲突出档分并写明两种来源。没有静默修正官方原文，也没有用出档分覆盖专业最低分。

玉林公费师范中，物理 452 组“物理学(初中,玉林市陆川县)”分列两行，历史 430 组“应用心理学(义教,玉林市博白县)”也分列两行，原文未说明子计划差异。保留不同源行和人数，均标记“原文分列待核实”，不要自动汇成一个专业最低分。公费师范的定向服务地区、户籍、体检和口语等原文要求保存在注释中。

玉林页面最初发布时间为 2026-07-11，页面随后增加录取结果，但未逐项列明更新日期。来源表不把最初发布日期当作所有录取结果的可得日期。

玉林艺术、体育、体育公费师范、预科不混入此专业表；预科只保留于另行采集的专业组资料中。齐齐哈尔“同分排位”不是全区位次，原样留在注释。所有专业结果都不能据此承诺未来年份录取。

## 核验

`quality-major.json` 保存各校头、中、尾抽样、源表列语义、人数核对及原文异常。已完成 HTML 合并单元格展开与重叠检查、专业最低/平均/最高分大小关系、2026 年份检查、记录 ID 唯一性、字段范围、来源外键检查。东北石油逐专业计划与录取均与原表整体行核对：物理 166 人、历史 24 人；重庆工程录取前计划为历史 10 人、物理 108 人。山东交通的 60 人只是逐行录取数合计，没有转成计划。

## 公开复现

只需要 Python 3.9 及以上版本的标准库，无第三方依赖、登录或密钥。在同一个目录保存：

- `collect.py`
- `collect-major.py`（公共解析器和玉林处理函数）
- `collect-additional-major.py`（完整的 5 校重建入口）

从官方页面下载并重建：

```sh
python3 collect.py --refresh
python3 collect-additional-major.py --refresh
```

第二步依赖第一步生成的 `cutoffs-first-round.json` 和 `sources.json`，用于玉林资格标签和出档分交叉检查。已有本地原始页时去掉 `--refresh` 可复用缓存。不要单独运行 `collect-major.py` 作为最终入口，否则只生成玉林子集。官方网页发生结构或数字变化时，断言可能停止，需要重新人工核对，不能绕过检查改年份。

公开仓库可以保存结构化事实、来源表、哈希、脚本和本说明。`raw/` 内官方整页 HTML 及 `*-expanded*.json` 仅作本地证据，不发布原始整页镜像。刷新会重新计算 SHA-256 与访问时间，重新下载的网页可能与本次快照不同。
